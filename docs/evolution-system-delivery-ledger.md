### Checked-byte to executed-byte closure

The artifact hash previously excluded Python cache products while the central
executor mounted the complete host bot directory at `/bot`. Python `-B` stops
cache writes but does not disable reads: an unchecked-hash
`__pycache__/policy.<tag>.pyc` or `precompute.<tag>.pyc` can override the
content-bound source. This created both an unbound-byte path and a
check-to-launch race across native evaluation, ratings, precommit, Arena and
formal certification.

The repaired boundary has one causal chain. Strict active layout rejects cache
directories and top-level bytecode; `.task_context` is permitted only by an
explicit Worker-phase call. Before any endpoint is consumed, the central
executor reads the exact top-level source files through no-follow descriptors,
reconstructs and verifies the expected artifact hash and required five-file
set, seals each captured payload in a write/grow/shrink-sealed memfd, and gives
the child a new `/bot` containing only those read-only files. The host bot
directory is never mounted. Python still starts with `-I -B` as defense in
depth, but neither flag is treated as the content-binding mechanism.

The same projection is now consumed by direct native matches (and therefore
rating/precommit), official certification, diagnostic Arena, the official wire
probe, national decision fixtures, and the runtime probe. The managed execution
identity advances to `pok-managed-executor-identity-v2`; the tracked formal
profile advances to
`official-exe-2021-wine9-managed-executor-v6` and binds the sealed-source
contract and source hash.

### Paired namespace and stopped-runtime reconciliation closure

The initial reset/recovery path treated any annotated completion or high-water
tag as numeric authority, and production, reset and reconciliation each parsed
the refs independently. A completion-only or high-water-only ref could
therefore advance one consumer but not another. The checkpoint envelope also
did not bind the live abandon-chain head, while generic cleanup cleared the
checkpoint before deleting the candidate. That ordering had a real crash
window: an orphan candidate could remain after the only routable control state
was gone.

The repaired implementation has one canonical paired-tag namespace resolver.
A version is numeric authority only when both exact annotated refs peel to the
same commit. Epoch initialization separately proves that the highest v143+
namespace version is the highest eligible five-file/tag-tree/signed-certificate
publication. Schema-2 checkpoints bind published high-water, abandon floor,
unique chain-head digest and allocation floor. A repeated terminal append is
idempotent only while its exact receipt remains the sole chain head; replay of
an older matching checkpoint fails closed.

Generic abandonment now shares the publication mutex and first persists both a
transaction claim and the typed live launch barrier. The claim binds the full
checkpoint CAS identity, reason, Git HEAD and exact candidate manifest before
the receipt or candidate path can change. Receipt creation/replay proves the
ledger inode and parent durable; completion/high-water refs, `.completed`, Git
tracking and the manifest are rechecked immediately before an atomic move into
a content-addressed transaction quarantine. Both rename parents are synced
before the full-identity checkpoint CAS, and a terminal transaction receipt is
durable before the live claim is cleared. The quarantine remains zero-authority
preimage evidence rather than being deleted or adopted.

Claim, receipt, Git-predicate, source/quarantine XOR, manifest, rename, fsync or
CAS failure fails closed with the recovery barrier intact. Retries re-fsync
already-published ledger and directory effects instead of assuming a raised
operation did not land. The stopped-runtime CLI consumes the same schema-2
transaction kernel and separately retains a narrow schema-1 compatibility path
for the historical clear-before-delete window; drift is preserved. Preparation
likewise never removes or adopts an existing target: only the exact live bytes
revalidated by the checkpoint-owned prepared-artifact contract may resume.

Namespace reads are also fail-closed across time. If the paired-tag authority
snapshot is unavailable or no longer matches the high-water read, initialization
is false and the published/active Bot projection is emptied, so scheduler,
prompts, API and dashboard cannot temporarily consume scanned artifacts as
authority.

Legacy reconciliation claims now validate every nested candidate, checkpoint,
ledger, cost-scope and runtime-control field. Runtime-control names are a
unique allowlist, not paths. Archive roots are canonical direct children of the
runtime reconciliation root, and every existing/created archive ancestor and
destination directory must be a real non-symlink directory before a claim or
move. Legacy rows remain raw quarantined bytes with authority weight zero.
