# Worker 1 Task Context: River call_margin cap + Turn value raise tier

## Source: v108 → v109 (offensive sizing + fold equity fix)

## WHY (H2H + battle experience evidence)
- **River fold=0%** across ALL 46800+ matches (bot_stats: river call=74-82%, allin=1-4%, fold=0%). This is the PRIMARY LEAK.
- Root cause: `call_margin` accumulation at strategy.py:925-941 inflates the call-vs-fold equity comparison at line 1026 (`realized_rate < pot_odds + call_margin`). On the river, call_margin accumulates:
  - line_strength + check_resistance (up to ~0.10-0.15 total from line_reading)
  - 0.50 * nutted_risk["risk"]
  - bluff_heavy_call_widen (variable)
  - +0.04 (river weak hand, line 938)
  - +0.05 (paired board fold_to_raise, line 940)
- Result: A hand with made_strength=0.30 facing a 0.7x pot river bet has pot_odds≈0.29, realized_rate≈0.30, but call_margin=0.10-0.18 → 0.30 < 0.29+0.15=0.44 → CALL (should fold).
- This is a DISTINCT decision point from the EXHAUSTED all-in/commitment guards (v90 SPR gate, v92 board-texture fold, v103 single-reraise guard targeted all-in/SPR paths, NOT the standard call-vs-fold equity comparison).
- **Turn avg_raise=0.4x pot** across all matches. There's `river_value_raise_tier()` for river (0.50-0.82 strength) but NO turn equivalent. Turn value raises rely on `choose_raise()` base ratio=0.70 but get capped to 0.30-0.40 by thin_cap/induce_mode.

## WHAT

### CHANGE 1: River call_margin cap (strategy.py ~line 942)
After the call_margin accumulation block (after line 941) and BEFORE `realized_rate = realized_postflop_equity(...)` (line 942), add a cap that prevents margin inflation from blocking folds of weak hands facing large river bets.

### CHANGE 2: Turn value raise tier (strategy_helpers.py + strategy.py wiring)
Add `turn_value_raise_tier()` mirroring `river_value_raise_tier()` for turn (round_idx==2), graduated 0.55-0.75x pot.
