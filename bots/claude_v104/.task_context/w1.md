# Worker 1 Task: River Call-Off Equity Ceiling

## Problem Evidence

Replay spotlight shows the bot calling off stacks with medium hands on the river:
- G3H9: K6 two-pair on 2-4-6-4-Q, opponent raise_to 6309 (massive), bot all-in → -20K
- G5H0: K9 two-pair on 6-6-K-T-7, opponent raise_to 6149, bot all-in → -20K  
- G0H50: AQ one-pair on K-4-5-3-3, bot all-in → -20K
- G6H11: 6T one-pair on 9-5-2-5-Q, bot all-in → -20K

Bot action stats: river fold=9.1%. Battle experience (2000+ matchups v13-v104): "0% postflop fold" universal, "allin≥11-31% = loser signal" confirmed in 9 loser cases. "allin≤6% winner-zone".

## Current Code Gap

In strategy.py `get_action()`, the all-in/shove commit paths (lines 848-882 for opponent_allin, lines 884-911 for to_call>=my_chips) use:
  `return -2 if win_rate >= jam_odds + jam_buffer or anti_lock_jam_continue else -1`

`jam_buffer` is clamped to [0.0, 0.14]. With pot odds ~0.40, bot needs only win_rate >= 0.54 to call off. For two-pair facing a massive river shove, simulation often gives 0.55+ — bot calls off and loses 20K.

The existing pre-filters (hard_repressure_fold needs repeated_raise_trap=2+ raises; value_heavy line_label needs VALUE_PRESSURE_THRESHOLD=0.65; paired_board_stackoff needs paired board) are all CONDITIONAL and miss many spots where the opponent shoves with a polarized range on an unpaired board.

## Solution: _river_subpremium_commitment_penalty()

Add a new function `_river_subpremium_commitment_penalty(round_idx, made_strength, value_profile, draw_strength)` that returns a POSITIVE penalty (float) to add to `jam_buffer` / `shove_buffer` before the clamp.

### Function skeleton:
```python
def _river_subpremium_commitment_penalty(round_idx, made_strength, value_profile, draw_strength):
    """Extra equity required to call off a river all-in/shove with a sub-premium hand.
    
    Facing a polarized shove on the river, medium hands (one-pair, weak two-pair) 
    are bluff-catchers at best. This adds a made_strength-scaled penalty so the bot
    requires higher equity before committing, preventing catastrophic stack-offs.
    Returns 0.0 for nut hands, strong draws, or non-river spots.
    """
    if round_idx != 3:
        return 0.0
    tier = value_profile.get("tier", "none") if value_profile else "none"
    if tier == "nut":
        return 0.0
    if draw_strength >= 0.18:
        return 0.0
    if made_strength >= 0.55:  # trips+ — legitimate stack-off territory
        return 0.0
    # Scale penalty: one-pair (~0.25) gets ~0.18, two-pair (~0.42) gets ~0.10
    # Linear interpolation: penalty = 0.20 * (0.55 - made_strength) / 0.30
    deficit = 0.55 - made_strength
    penalty = 0.20 * deficit / 0.30  # max 0.20 at made_strength=0.25
    # Slight reduction for "strong" tier (e.g. top-pair-good-kicker) since these 
    # are sometimes worth calling off vs aggressive bluffers
    if tier == "strong":
        penalty *= 0.65
    return clamp(penalty, 0.0, 0.20)
```

### Wiring in get_action():

In the `state["opponent_allin"]` block (after line 881, BEFORE the clamp):
```python
        jam_buffer += _river_subpremium_commitment_penalty(round_idx, made_strength, value_profile, draw_strength)
```

In the `to_call >= my_chips` block (after line 910, BEFORE the clamp):
```python
        shove_buffer += _river_subpremium_commitment_penalty(round_idx, made_strength, value_profile, draw_strength)
```

IMPORTANT: The penalty is added BEFORE `clamp(jam_buffer, 0.0, 0.14)`. The clamp upper bound must be RAISED to accommodate the penalty. Change the clamp from `0.14` to `0.30` on both lines. This is critical — without raising the clamp, the penalty is silently absorbed.

### Effect:
- River shove with one-pair (made_strength ~0.25): needs win_rate >= pot_odds + 0.05 + 0.20 = pot_odds + 0.25 (was pot_odds + 0.05). Bot folds more one-pair all-ins.
- River shove with two-pair (made_strength ~0.42, tier=strong): needs win_rate >= pot_odds + 0.05 + 0.10*0.65 = pot_odds + 0.115 (was pot_odds + 0.05). Tighter but still calls with strong two-pair.
- River shove with trips+ (made_strength >= 0.55): no change — legitimate stack-off.
- Non-river spots: no change.
