## 1. 结论

**B 路线的局部 M3 小博弈门通过，但这不等于 M4 或 HUNL 在线搜索完成。**

原提交的 Kuhn/Leduc 游戏、External-Sampling MCCFR、Linear/CFR+/DCFR、exact best response/exploitability 和 deterministic checkpoint/shard 数值均可复现。复核发现的主要问题不是已知数字错误，而是证据闭包不足：

1. External-Sampling 只有收敛趋势，没有独立 full-tree regret delta 期望对拍；
2. best response 只有 Kuhn 已知均衡，没有纯策略穷举或非均匀 Leduc 外部对拍；
3. shard 只证明集合完整，没有拒绝 sample 被放入错误 deterministic shard；
4. 原子文件只 `fsync` 文件，没有 `fsync` rename 后目录；
5. M3 阶段要求的 safe/depth-limited small-game 基础完全缺失。

上述五项均在本复核中补齐并进入自动测试。没有改变 MCCFR accumulator 数值语义，三份冻结配置的最终 state SHA-256 与原报告逐字一致。

## 3. 原始来源复核

- External-Sampling 的 traverser 枚举、chance/opponent sampling 与两人 simple averaging 对照 Lanctot et al. 2009 论文及 OpenSpiel `ExternalSamplingSolver`。
- Linear/DCFR 对照 Brown、Sandholm 2019：本实现的 post-add 折扣递推与“第 `t` 轮给 regret/average strategy 权重 `t`”的等价形式一致。OpenSpiel 固定源码也在 accumulator 更新后按新符号折扣；其文件自身的未验证复现实验警告仍保留，不把 OpenSpiel 当论文证明。
- safe resolve 对照 safe/nested subgame solving 的 top opponent counterfactual-value 边界，但当前实现是小型 exhaustive `functional adaptation`，不是 Libratus gadget 复刻。

来源、版本、许可证和 falsifier 的更新见 `m0_research_license_matrix.md`。OpenSpiel 只安装到 `/tmp` 做隔离审计；wheel 和运行时信息见 `manifests/m3_audit_dependencies.json`。

### 7.2 Exact Kuhn safe replacement

对 uniform blueprint，27 个 call-probability grid candidates 中 9 个通过安全门；safe solver 选择 `(rank0, rank1, rank2) = (0, 1, 1)`：

- top P1 infoset margins：`(1/12, 1/12, 0)`；
- blueprint exploitability：`0.4583333333333333`；
- candidate exploitability：`0.375`；
- resolver on-policy value：`1/3`。

反例 blueprint 的原 response 为 `(0, 2/3, 1)`：

- plain resolve 选择 `(0, 1, 1)`，resolver value 提升到 `1/3`；
- 但 top margin 为 `-1/36 = -0.02777777777777779`，exploitability 从 `0.3611111111111111` 上升到 `0.375`，因此拒绝；
- safe mode 在 28 个候选中仅 2 个合格，选择原 blueprint `(0, 2/3, 1)`，exploitability 不变。

另一个 adversarial candidate `(1, 0, 0)` 的最小 margin 为 `-0.25`，被拒绝；任何 subtree 外策略变化也直接失败。

## 10. M4 前剩余硬缺口

1. 此项历史缺口已由 Common `cc8beed2` 和内容绑定 adapter 关闭；正式 TCP decision lease/deadline/resource/wire 接线仍属 M4/M10，而非 M3；
2. 没有 HUNL 169/1326 hand abstraction、postflop cluster version、dynamic action abstraction 或 blueprint table schema；
3. 当前 per-sample JSON shard 是 correctness format，没有多进程执行、压缩稀疏存储、mmap 或 crash-recovery supervisor；
4. 没有 blueprint-only native TCP runtime，因此尚不能完成一场国赛比赛；
5. depth-limited leaf 目前是 full-state exact rollout，不是双方 range-conditioned counterfactual value vector；
6. safe resolver 只处理 Kuhn 一个公共历史，依赖完整树 exact BR；没有 Leduc public-range gadget、multi-root opponent range、off-tree sizing 或可扩展安全证明；
7. 未做大规模训练、资产导出、部署打包、官方兼容性或强度评测。

因此下一步可以进入 **M4 的实现准备和小规模 blueprint-only vertical slice**，但必须先合入冻结 Common 合同；不得以本报告为依据跳到神经叶值或 HUNL 大训练。
