# Worker 1 Task Brief: River Value-Raise Broadening (OFFENSIVE +EV)

## Evidence
- Bot action stats (n=1029 river decisions): raise=22.1%, call=6.2%, fold=10.4% (rest=check/0).
  Match analysis: river raise 8-21% across matchups, avg_raise 0.4-0.6x pot.
- Strong/nut river hands UNDERBET because:
  (a) `river_value_raise_tier()` (strategy_helpers.py:327) EXCLUDES nut hands (`if tier=='nut': return None`)
  (b) `river_value_raise_tier()` ONLY fires when `to_call==0` (unraised river) — there is
      NO dedicated value-raise branch when facing a river bet.
- The facing-bet path (strategy.py:925-1167) reaches `choose_raise` only via the generic
  `win_rate >= max(strong, pot_odds + 0.12)` gate at line 1141. There is no graduated
  river-specific value sizing for nut/strong hands facing a bet → they default to call (0).

## Direction Constraint Compliance
This is an OFFENSIVE +EV branch that ADDS a raise line where none exists (Direction Auditor
option 1). It is NOT a fold/call modification, NOT a defensive guard, NOT a sizing-cap
constant tune. It creates a NEW aggressor branch in `river_value_raise_tier` itself.

## Tasks

### Task A — Broaden `river_value_raise_tier()` (strategy_helpers.py:327-360)

Current function ONLY fires when `to_call==0` and `made_strength in [0.50, 0.82]` and
excludes nut tier. Extend it to also fire when FACING a river bet for nut/strong hands.

Add a NEW branch at the TOP of `river_value_raise_tier` (before the existing `to_call != 0`
return None) that handles facing-bet value raises:

```python
def river_value_raise_tier(round_idx, to_call, made_strength, value_profile, board_texture, opponent_model, pot, my_chips, min_raise, my_round_bet):
    if round_idx != 3:
        return None
    tier = value_profile.get('tier', 'none') if value_profile else 'none'
    confidence = opponent_model.get('confidence', 0.0)
    fold_to_raise = opponent_model.get('fold_to_raise', 0.44)
    # NEW BRANCH A: facing a river bet with nut/strong hands -> value raise
    if to_call > 0:
        # Only nut/strong hands value-raise facing a bet (thin hands just call).
        if tier not in ('nut', 'strong'):
            return None
        if made_strength < 0.70:
            return None
        if board_texture is not None and board_texture.get('dynamic', False):
            return None  # avoid raising into dynamic/scary rivers
        if nutted_risk_blocked(board_texture, value_profile):
            return None  # safety: defer if board has obvious better-than-our-hand risk
        # Do not raise if opponent almost never calls a raise (no value).
        if confidence >= 0.20 and opponent_model.get('call_down_rate', 0.50) < 0.30:
            return None
        # Graduated sizing: nut hands 0.70-0.85x pot; strong hands 0.55-0.70x pot.
        t = clamp((made_strength - 0.70) / 0.25, 0.0, 1.0)
        ratio = 0.55 + 0.30 * t
        if confidence >= 0.20 and fold_to_raise >= 0.52:
            ratio += 0.06 * confidence  # bigger vs fit-or-fold opponents
        ratio = clamp(ratio, 0.50, 0.90)
        target_total = my_round_bet + to_call + int((pot + to_call) * ratio)
        amount = target_total - my_round_bet
        amount = max(min_raise, amount)
        amount = min(amount, my_chips - 1)
        if amount < min_raise or amount >= my_chips:
            return None
        return amount
    # EXISTING unraised path: now also allow nut tier (was excluded).
    if made_strength < 0.50 or made_strength > 0.95:
        return None
    # ...keep existing logic but REMOVE the `if tier == 'nut': return None` line
    # so nut hands unraised also get a value bet (graduated higher).
```

Notes:
- The existing unraised-path tier=='nut' exclusion must be REMOVED so nut hands get a
  value bet (sized higher than strong hands). Cap made_strength upper bound at 0.95
  instead of 0.82 so very-nutted hands still get a bet (they currently fall through to
  generic path).
- Add a small helper `nutted_risk_blocked(board_texture, value_profile)` that returns True
  when board texture has a made-hand class higher than the bot's value tier (e.g. board
  has 4-to-a-flush/straight and we only have strong, not nut). This prevents raising into
  boards where opponent can have the effective nuts. Keep it conservative: return True
  only when `board_texture['dynamic']` is True OR when a paired board with high nutted_risk
  is flagged. If you cannot easily wire nutted_risk here, simply rely on the
  `board_texture['dynamic']` check already in the branch.

### Task B — Wire the facing-bet river value raise into strategy.py

In strategy.py at the `if to_call > 0:` block (line 925 onward), just BEFORE the generic
`if not preflop_defensive_only and (win_rate >= max(strong, pot_odds + 0.12) ...)` gate
(line 1141), insert a call to the broadened `river_value_raise_tier`:

```python
# NEW: river value raise facing a bet (graduated 0.55-0.85x pot) for nut/strong hands.
# This is an OFFENSIVE +EV branch; previously these hands just called.
if round_idx == 3 and value_profile is not None and value_profile.get('tier') in ('nut', 'strong') and made_strength >= 0.70:
    _rvr = river_value_raise_tier(
        round_idx, to_call, made_strength, value_profile, board_texture,
        opponent_model, pot, my_chips, state['min_raise_action'], state['my_round_bet'],
    )
    if _rvr is not None and _rvr > to_call:
        return _rvr
```

This must be placed BEFORE the generic raise gate so it takes priority for nut/strong
river hands facing a bet, but AFTER the existing fold guards (fragile_river_raise_fold,
should_fold_postflop, etc.) so it does not override legitimate folds. The nut/strong +
made_strength>=0.70 precondition already excludes the hands those guards target.
